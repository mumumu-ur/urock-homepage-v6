[PROJECT OVERVIEW]

주식회사 유락(UROCK) 공식 브랜드 웹사이트의 메인 최상단 Hero 영역을 제작한다.

이 Hero는 단순한 우주 이미지나 일반적인 SF 조종석이 아니다.

사용자는 거대한 AI 디지털 포렌식 분석실 또는 포렌식 관제센터 내부에 위치하며,
거대한 관측창 너머로 방대한 디지털 증거의 세계인
‘데이터 우주(Data Universe)’를 바라보고 있다.

이 공간은 디지털 증거를 수집·탐색·분석하고,
흩어진 흔적을 조직이 판단할 수 있는 결과로 전환하는
AI 디지털 포렌식 우주선의 조종석이다.

Hero의 최종 컨셉명:

AI FORENSIC SPACECRAFT COCKPIT

데이터 우주 속에 남은 디지털 흔적을 탐색하고,
관계와 맥락을 연결해 판단 가능한 결과를 만드는
AI 디지털 포렌식 관제 공간으로 표현한다.

기존 UROCK Claude Design System에 정의된
디자인 토큰, 타이포그래피, 버튼, 카드, 레이아웃,
모션 및 반응형 규칙을 우선적으로 재사용한다.

새로운 디자인 토큰이나 중복 컴포넌트를 임의로 생성하지 않는다.

================================================================================
1. HERO의 비즈니스 목적
================================================================================

이 Hero는 브랜드 감성만 보여주는 장식 영역이 아니다.

사용자가 첫 화면을 본 뒤 3초 안에 다음 내용을 이해해야 한다.

1. 유락은 AI 디지털 포렌식 전문기업이다.
2. 디지털 흔적과 증거를 분석하는 기업이다.
3. 현장형 분석, 원격 PC 점검, 스마트기기 미디어 흔적 점검,
   스마트기기 데이터 삭제와 전문 서비스를 제공한다.
4. 외부 네트워크 사용이 제한되는 환경을 고려한
   폐쇄망·온디바이스 AI 기술을 개발하고 있다.
5. 공공기관, 기업 감사·보안 조직, 연구소·제조 환경 등을 대상으로 한다.
6. 사용자는 솔루션 탐색 또는 도입·데모 상담으로 이동할 수 있다.

Hero에서 제품 세부 기능과 하드웨어 사양을 장황하게 나열하지 않는다.

Hero 정보 위계:

고객이 얻는 결과
→ AI 디지털 포렌식 기업 정체성
→ 주요 해결 범위
→ 기술 차별성
→ 솔루션 탐색 또는 상담 CTA
→ 시네마틱 세계관과 모션

시각 효과가 텍스트보다 우선해서는 안 된다.

2. 사실 검증 원칙
================================================================================

확인되지 않은 성능·제품 상태·시장 지위는 생성하지 않는다.

다음 표현을 사용하지 않는다.

- 세계 최초
- 세계 유일
- 유일한 온디바이스 AI
- 글로벌 유일
- 인터넷이 끊겨도 모든 기능이 즉시 작동
- 모든 분석이 현장에서 즉시 완료
- 완벽한 보안
- 외부 유출 원천 차단
- 100% 탐지
- 모든 OS 완벽 지원
- Windows·macOS·Linux 기능 완전 동일
- 모든 제품이 온디바이스 AI 기반
- 모든 데이터 자동 분석
- 검증되지 않은 속도 또는 시간 단축률

온디바이스 AI와 폐쇄망 AI는 DFAS Edge 중심의 기술로 표현한다.

DFAS Edge가 개발 중인 경우:

“외부 연결이 제한된 현장을 고려한
폐쇄망·온디바이스 AI 포렌식 기술을 개발합니다.”

DFAS Edge의 상용화와 실제 제공 범위가 내부적으로 확인된 경우에만:

“외부 연결이 제한된 현장에서 운용되는
폐쇄망·온디바이스 AI 포렌식 기술을 제공합니다.”

로 변경할 수 있다.

Hero의 메인 카피에서
유락의 모든 솔루션이 폐쇄망 또는 온디바이스 AI로 작동하는 것처럼 표현하지 않는다.

- Enterprise Security Command Center
- Forensic Operations Room

- 타임라인 노드

- 데이터 신호 입자

- Constellation Node
- Orbit Path
- Reality Core

별, 성운, 은하, 행성과 같은 우주 요소를 사용할 수 있으나
사진 그대로의 천문 이미지가 화면의 중심이 되어서는 안 된다.

다음 방식으로 추상화한다.

- 별 → 데이터 노드
- 성운 → Data Aurora
- 은하 → 데이터 밀도와 관계망
- 행성 → 대규모 데이터 클러스터 또는 Reality Core
- 유성 → 이동 중인 데이터 패킷
- 궤도 → 사건·시간·행위의 연결 관계
- 우주 파편 → 분산된 증거 조각

실제 우주 관광이나 우주 탐험 광고처럼 보이지 않게 한다.

Hero를 본 사용자가
‘우주 기업’이 아니라
‘첨단 AI 디지털 포렌식 기업’으로 인식해야 한다.

대안 시퀀스는 별도의 버전 테스트용으로만 보관한다.

두 시퀀스를 동시에 혼합하지 않는다.

--------------------------------------------------
[텍스트 등장 방식]
--------------------------------------------------

각 문구는 다음 효과 중 2~3개만 조합한다.

- Character-by-character Reveal
- Word-by-word Reveal
- Line Mask Reveal
- Clip-path Vertical Reveal
- Opacity Fade
- 8~20px 이내의 Translate Y
- Slight Letter-spacing Contraction
- Soft Blur to Sharp
- Scan-line Reveal
- Data Sweep Reveal

한 문구에 모든 효과를 동시에 사용하지 않는다.

권장 등장:

1. 텍스트는 약한 Blur 상태로 시작
2. 왼쪽에서 오른쪽으로 Mask가 열림
3. 문자 또는 단어가 20~40ms 간격으로 연속 등장
4. Letter-spacing이 넓은 상태에서 정상값으로 수렴
5. 최종 1.2~1.8초 유지
6. Opacity 감소와 함께 위쪽으로 8~12px 이동
7. 다음 문구 등장

‘촤르륵’ 느낌은
문자 수가 많은 경우 Character Stagger,
짧은 문구는 Word Stagger로 구현한다.

과도한 타이핑 커서나 Terminal 효과는 사용하지 않는다.

해커 콘솔처럼 한 글자씩 입력되는 Typewriter 효과가 아니라
프리미엄 광고 영상의 편집 타이포그래피처럼 보여야 한다.

--------------------------------------------------
[권장 타이밍]
--------------------------------------------------

초기 Delay:
300~500ms

각 문구 Reveal:
500~800ms

각 문구 유지:
1,000~1,600ms

각 문구 Exit:
300~500ms

다음 문구 간 Gap:
100~250ms

최종 H1 Reveal:
800~1,200ms

전체 Intro:
약 7~11초

전체 Intro가 너무 길어 사용자의 탐색을 방해하지 않게 한다.

최종 H1과 CTA는 최대 3초 이내에 부분적으로라도 인식 가능해야 한다.

첫 화면에서 CTA가 7초 이상 완전히 숨겨져 있어서는 안 된다.

권장 방식:

- CTA는 Intro 1.5~2.5초 후 낮은 투명도로 등장
- 최종 H1 도달 시 완전 활성화
- 사용자가 Pointer, Keyboard 또는 Scroll 입력을 하면 즉시 활성화

--------------------------------------------------
[텍스트 종료 상태]
--------------------------------------------------

Intro 종료 후 다음 요소를 고정한다.

- Eyebrow
- H1
- Description
- 기술 보조 문장
- Primary CTA
- Secondary CTA
- 하단 Scope Navigation

Intro 종료 후 텍스트가 다시 사라지거나
무한 순환하지 않는다.

--------------------------------------------------
[텍스트 접근성]
--------------------------------------------------

스크린리더가 Sequence 01~06을 전부 반복해서 읽지 않도록 한다.

장식용 순차 문구는 aria-hidden="true"로 처리한다.

스크린리더에는 다음 최종 콘텐츠만 제공한다.

- Eyebrow
- H1
- Description
- CTA

SEO와 접근성을 위해
최종 H1과 설명은 실제 HTML 텍스트로 항상 존재해야 한다.

텍스트를 Canvas, SVG Path 또는 이미지 안에 넣지 않는다.

prefers-reduced-motion: reduce 환경에서는
광고형 시퀀스를 완전히 생략하고
최종 H1, 설명, CTA를 즉시 표시한다.

================================================================================
8. HERO 레이어 구조
================================================================================

Hero는 최소 3단계의 깊이를 가진 Perspective Layer로 구성한다.

--------------------------------------------------
LAYER 01. FOREGROUND
--------------------------------------------------

카메라와 가장 가까운 레이어다.

구성 요소:

- AI 디지털 포렌식 분석 장비 일부
- 투명 홀로그램 패널
- 증거 추적 UI
- 데이터 스캔 인터페이스
- 유리 반사
- 조종석 가장자리
- 공중에 떠 있는 분석 패널
- 전면 Light Particle
- 프레임 밖으로 일부 잘린 장비
- 포렌식 데이터 패널의 일부

Foreground는 화면 좌우 또는 하단 가장자리에 배치해
사용자가 실제 관제센터 안에 앉아 있는 느낌을 만든다.

텍스트 영역 위를 직접 가리지 않는다.

마우스 움직임에 가장 크게 반응한다.

권장 반응 범위:

- X축: 최대 12~20px
- Y축: 최대 8~14px
- Rotation: 최대 0.5~1.2도

과도한 이동이나 3D Tilt는 사용하지 않는다.

--------------------------------------------------
LAYER 02. MIDGROUND
--------------------------------------------------

중간 깊이 레이어다.

구성 요소:

- 우주선 또는 관제센터 구조물
- 거대한 관측창 프레임
- Mission Control Dashboard
- 포렌식 모니터링 장비
- 분석 디스플레이
- 투명 Interface Panel
- Reality Core 주변 장비
- 데이터 연결선

Midground는 화면의 공간 구조와 안정감을 담당한다.

Foreground보다 적게 움직인다.

권장 반응 범위:

- X축: 최대 6~12px
- Y축: 최대 4~8px
- Rotation: 최대 0.2~0.6도

--------------------------------------------------
LAYER 03. BACKGROUND
--------------------------------------------------

가장 먼 레이어다.

구성 요소:

- 추상화된 별과 데이터 노드
- Data Aurora
- 은하처럼 보이는 데이터 클러스터
- 데이터 파편
- 증거 조각
- Orbit Path
- Constellation Node
- Reality Core
- 미세한 빛 입자
- 데이터 신호
- 낮은 대비의 행성형 데이터 구조

Background는 매우 천천히 움직인다.

권장 반응 범위:

- X축: 최대 2~6px
- Y축: 최대 2~4px
- Scale: 최대 1.00~1.02

================================================================================
9. HERO 초기 진입 모션
================================================================================

페이지가 처음 표시될 때 다음 순서로 연출한다.

1. primary-02 배경 즉시 표시
2. 우주선 조종석의 어두운 실루엣 표시
3. 관측창 외부의 Data Aurora가 천천히 활성화
4. Foreground 장비의 작은 Indicator 점등
5. Connection Ring 또는 Reality Core가 낮은 밝기로 활성화
6. 광고형 텍스트 Sequence 시작
7. HUD 및 데이터 노드가 순차적으로 연결
8. 최종 H1 표시
9. CTA 완전 활성화
10. Scope Navigation 표시

초기 모션이 완료되기 전에도
페이지 핵심 콘텐츠가 DOM에서 접근 가능해야 한다.

모션 코드가 늦게 로드되더라도
빈 화면이 노출되지 않게 한다.

================================================================================
10. 마우스 인터랙션
================================================================================

작은 마우스 움직임에 반응하는
절제된 3D Parallax를 구현한다.

- Foreground: 가장 크게 반응
- Midground: 중간 정도 반응
- Background: 최소 반응
- 텍스트 컨테이너: 움직이지 않거나 최대 1~2px만 반응

텍스트와 CTA는 포인터 움직임에 따라 흔들리지 않게 한다.

사용자가 화면 가장자리로 Pointer를 이동해도
레이어가 잘리거나 빈 공간이 보이지 않게 Overscan을 적용한다.

Pointer Leave 시
각 레이어는 부드럽게 원래 위치로 돌아온다.

권장 복귀 시간:

400~700ms

모바일과 터치 환경에서는
마우스 기반 Parallax를 비활성화한다.

기기의 자이로 센서를 자동 요청하거나 사용하지 않는다.

================================================================================
11. 스크롤 인터랙션
================================================================================

사용자가 Hero를 스크롤하면
카메라가 AI 디지털 포렌식 관제센터 내부를 지나
관측창과 데이터 우주를 향해 천천히 전진하는 느낌을 구현한다.

이동 서사:

우주선 내부 프레임
→ 포렌식 분석 장비
→ 홀로그램 분석 인터페이스
→ 관측창
→ 디지털 증거의 공간
→ 데이터 우주
→ 다음 메인 섹션

Scroll Driven Camera Movement를 사용하되
사용자의 스크롤을 강제로 제어하지 않는다.

Scroll Hijacking 금지.

Hero 전체를 장시간 Pinning하지 않는다.

권장:

- Hero 전체 높이: 100~140vh
- Motion Scroll Range: 약 40~70vh
- 실제 페이지 스크롤 속도를 유지
- 카메라 전진은 Transform과 Scale 기반
- 다음 섹션으로 자연스럽게 연결

스크롤에 따른 변화:

0~20%
- 우주선 내부와 텍스트 중심
- Foreground 장비 명확

20~45%
- Foreground가 화면 바깥으로 서서히 이동
- 관측창과 Midground 강조

45~70%
- Reality Core와 데이터 노드 활성화
- Background Scale이 미세하게 증가

70~100%
- 관측창 너머 데이터 우주가 확장
- Hero 텍스트와 CTA는 부드럽게 감소
- 다음 섹션의 연결 노드 또는 Section Divider 노출

텍스트가 스크롤 시작과 동시에 빠르게 사라지지 않게 한다.

사용자가 H1과 CTA를 읽을 수 있는 구간을 충분히 확보한다.

================================================================================
13. HUD와 포렌식 인터페이스
================================================================================

HUD는 장식용 그래픽이 아니라
디지털 포렌식 분석이라는 의미를 전달해야 한다.

사용 가능한 정보 유형:

- FILE ACTIVITY
- TIMELINE
- DEVICE CONNECTION
- USER ACTIVITY
- MEDIA TRACE
- EVIDENCE NODE
- ANALYSIS STATUS
- LOCAL AI
- REPORT GENERATED
- CONNECTION PATH

확인되지 않은 실제 제품 성능이나 분석 결과처럼 보이는
가짜 수치와 고객 데이터를 생성하지 않는다.

금지 예시:

- 99.99% Accuracy
- 100% Complete
- 3.2 Billion Evidence Files
- 실재하지 않는 기관명
- 실제 사건번호처럼 보이는 데이터
- 실제 개인정보
- 임의 IP 주소 또는 사용자명
- 임의 범죄 사건 정보

필요한 경우 추상적 상태값을 사용한다.

- ANALYZING
- CONNECTED
- LOCAL PROCESSING
- TRACE FOUND
- REPORT READY

단, UI 전체를 영문 상태값으로 도배하지 않는다.

HUD는 배경 레이어 수준에서만 사용한다.

14. CTA 인터랙션
================================================================================

[Primary CTA]

솔루션 살펴보기

스타일:

- Background: primary-01
- 기존 Filled Button 컴포넌트
- 기존 Radius Token
- 최소 높이 48px
- arrow_downward 또는 arrow_outward 아이콘

Hover:

- Primary Glow 증가
- Connection Ring 4~6도 회전
- 버튼 자체 이동은 최대 2px

Focus:

- primary-01 또는 대비 가능한 Focus Ring
- Hover와 구분되는 상태

[Secondary CTA]

도입·데모 상담

스타일:

- Dark Glass 또는 Outline Button
- 충분한 텍스트 대비
- 기존 Secondary Button 컴포넌트 재사용

두 CTA를 과도하게 떨어뜨리지 않는다.

Mobile에서는 두 버튼을 세로 또는 가로 2열로 배치하되,
각 버튼의 터치 영역은 최소 44px 이상 확보한다.

================================================================================
15. 반응형
================================================================================

[Desktop]

- Hero Min Height: 800~900px
- 12 Column Grid
- Text Area: 약 5~6 Columns
- Visual Area: 약 6~7 Columns
- Cockpit Frame과 관측창 모두 표시
- Mouse Parallax 활성화
- Scroll Camera Movement 활성화
- 광고형 Text Sequence 활성화
- Volumetric Lighting 사용 가능

[Tablet]

- 8 Column Grid
- Text와 Visual을 겹치지 않게 구성
- Foreground Object 30~50% 제거
- Parallax 이동 범위 축소
- Scroll Camera Scale 축소
- HUD 정보량 축소
- Text Sequence 유지 가능
- CTA는 명확히 노출

[Mobile]

- Hero Min Height: 720~820px
- 4 Column Grid
- Side Padding: 약 20px
- 텍스트 우선
- 실제 3D Parallax 비활성화
- 정적 또는 매우 느린 2~3 Layer Composition
- Scroll Camera Movement 단순화
- 복잡한 Perspective 제거
- Background Poster Image 또는 경량 CSS/SVG 사용
- 광고형 Text Sequence는 3~4단계로 축소 가능
- CTA는 초기 화면 안에서 확인 가능
- Scope Navigation은 Horizontal Scroll Chip 또는 세로 리스트
- Hover 전용 정보 금지

Mobile 축약 Sequence:

1. 남겨진 기록.
2. 연결되는 흔적.
3. 판단 가능한 결과.
4. 최종 H1

저성능 기기 또는 Data Saver 환경에서는
모션을 생략하고 최종 Hero 화면만 즉시 표시한다.

================================================================================
16. 접근성
================================================================================

WCAG 2.2 AA 수준을 목표로 한다.

필수 사항:

- 실제 H1 사용
- CTA는 실제 button 또는 a 요소 사용
- 키보드 탐색 가능
- Focus Visible 제공
- 텍스트 대비 확보
- 장식용 오브젝트 aria-hidden="true"
- 의미 있는 인터페이스에는 적절한 Label 제공
- 색상만으로 상태를 구분하지 않음
- 자동 재생 모션을 정지할 수 있는 방안 검토
- Reduced Motion 지원
- 고정된 텍스트 정보는 JavaScript와 무관하게 제공

prefers-reduced-motion: reduce 적용 시:

- 광고형 텍스트 시퀀스 제거
- Character Stagger 제거
- Parallax 제거
- Camera Movement 제거
- Node Blink 제거
- Orbit Rotation 제거
- Volumetric Light Animation 제거
- 최종 H1과 CTA 즉시 표시
- 100~160ms 이내의 단순 Fade만 허용

================================================================================
17. 성능 최적화
================================================================================

Hero의 시각적 몰입감 때문에 초기 로딩 성능을 희생하지 않는다.

[Rendering Strategy]

1단계:
primary-02 배경, H1, 설명, CTA 즉시 렌더링

2단계:
정적 Cockpit Poster 또는 Base Visual 표시

3단계:
광고형 텍스트 Sequence 활성화

4단계:
Parallax와 Scroll Motion 활성화

Progressive Enhancement를 사용한다.

JavaScript가 실패해도
H1, 설명, CTA와 핵심 Visual은 정상적으로 표시되어야 한다.

[Asset]

우선순위:

1. CSS Gradient
2. 경량 SVG
3. 최적화된 AVIF
4. WebP Fallback
5. 필요한 경우에만 WebM Video

금지:

- Base64 이미지
- 4K 배경 이미지
- 대형 투명 PNG
- 무압축 3D 렌더
- Hero 전체를 하나의 고용량 영상으로 구현
- 초기 로드 시 모든 입자와 HUD를 즉시 실행
- 외부 3D 엔진을 Hero 하나 때문에 신규 설치

3D 렌더 이미지를 사용할 경우:

- Desktop / Tablet / Mobile 별도 크기 제공
- AVIF 우선
- WebP Fallback
- Width와 Height 명시
- Aspect Ratio 고정
- LCP 후보는 하나로 제한

[JavaScript]

기존 프로젝트에 GSAP가 설치되어 있으면 재사용할 수 있다.

설치되어 있지 않다면
Hero 하나를 위해 대형 모션 라이브러리를 무조건 추가하지 않는다.

가능하면 다음을 우선한다.

- CSS Transform
- CSS Transition
- Web Animations API
- requestAnimationFrame
- IntersectionObserver

GSAP 사용 시:

- 필요한 모듈만 Import
- 전체 라이브러리 전역 Import 금지
- ScrollTrigger가 필요한 경우에만 Import
- Timeline Cleanup
- 컴포넌트 해제 시 이벤트 제거
- 화면 밖에서는 애니메이션 중지

[Animation Properties]

허용:

- transform
- translate3d
- scale
- rotate
- opacity
- clip-path의 단순 Reveal
- SVG stroke-dashoffset

지속 애니메이션 금지:

- top
- left
- width
- height
- margin
- padding
- 대형 filter blur
- 복잡한 box-shadow
- 수백 개 Particle
- 대규모 SVG Filter
- 모든 HUD 요소의 지속적인 움직임

동시에 움직이는 핵심 요소는
가능하면 12개 이하로 제한한다.

================================================================================
20. 최종 검수
================================================================================

구현 완료 후 다음 항목을 자체 검수한다.

1. 첫 화면에서 AI 디지털 포렌식 기업임을 이해할 수 있는가.
2. 우주 기업이나 게임 사이트로 오인되지 않는가.
3. H1이 실제 HTML 텍스트로 존재하는가.
4. 광고형 문구가 무한 반복되지 않는가.
5. 최종 H1과 CTA가 Intro 종료 후 고정되는가.
6. 사용자의 Scroll, Click, Keyboard 입력 시 Intro를 건너뛸 수 있는가.
7. CTA가 지나치게 늦게 등장하지 않는가.
8. 모든 핵심 텍스트를 3초 내 일부라도 인식할 수 있는가.
9. Foreground, Midground, Background 깊이 차이가 절제되어 있는가.
10. 텍스트 영역이 Parallax로 흔들리지 않는가.
11. Scroll Hijacking이 없는가.
12. Hero가 과도하게 긴 Pin Section이 아닌가.
13. Reduced Motion에서 모든 복잡한 모션이 제거되는가.
14. Mobile에서 Mouse Parallax가 제거되는가.
15. Mobile에서도 CTA가 명확히 보이는가.
16. primary-02가 Hero의 주요 배경으로 적용되었는가.
17. primary-01이 CTA와 활성 상태의 중심 컬러인가.
18. 과도한 네온과 사이버펑크 표현이 없는가.
19. 초록색 Matrix 코드비가 없는가.
20. 확인되지 않은 성능과 제품 기능이 생성되지 않았는가.
21. 유락의 모든 솔루션이 온디바이스 AI처럼 표현되지 않았는가.
22. DFAS Edge의 상태에 따라 ‘개발합니다/제공합니다’가 정확히 구분되었는가.
23. JavaScript 실패 시에도 H1과 CTA가 노출되는가.
24. LCP 요소가 하나로 제한되는가.
25. PC, Tablet, Mobile 화면이 모두 구현되었는가.
26. 모든 모션이 콘텐츠 가독성과 행동 유도를 방해하지 않는가.
